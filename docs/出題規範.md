# 出題規範（給出題者）

先讀 `CLAUDE.md`（專案總規範）。本檔是寫題目 JSON 的細節。資料、概念與關卡清單見 `docs/_data_lists.md`。
參考範例：`data/questions/map.json`、`data/questions/climate.json`、`data/cards/climate.json`。

## 鐵則
1. **只出課本教過的**。依據是康軒課本文字檔 `D:\geo-quest\_課本\_text\`（檔名前綴：1131上＝第一冊、1131下＝第二冊、1142上＝第三冊、1142下＝第四冊、1153上＝第五冊；不要用 1133上、1143下）。每個檔案是一課，含課文、圖說、充電站。先讀相關的課再出題。
2. **source 必填**，格式：「課本概念：康軒 3上第1課 歐洲的氣候（西風與北大西洋暖流）；資料：WMO 1991–2020」。不要寫「改寫自某年會考」，除非真的有。
3. **數字只能來自資料檔**。題幹、選項、解析裡出現的氣溫、降水、人口比例，一定要用 `check` 讓程式驗算（climate-value／climate-rank／pyramid-value／pyramid-rank）。課本圖表的數字（例如課本溫雨圖的年均溫）和 WMO 資料常常不同，**一律以資料檔為準**，不要抄課本數字。查不到可靠資料的數字不要出。
4. 沒有資料、又不是課本敘述的「事實」（例如某國某產品產量排名）不要自己寫。課本有寫的敘述性事實可以出，source 寫出處（冊、課）。
5. 新題 `status` 一律填 `"確認"`（家長不逐題審）。所以品質要自己把關：答案唯一、選項合理、沒有爭議。
6. 繁體中文、臺灣用語、國中生看得懂。題幹不要太長。干擾選項要「合理但錯」，不要放明顯亂來的選項。
7. `explain` 要說明「為什麼」，把現象連到通論原理，不只是重複答案。
8. 不要寫政治立場或價值判斷題。地名、國名用課本寫法。
9. **選項長度要平均**：正解不可以是唯一最長的選項（國中生會挑最長的）。干擾選項要和正解一樣具體，或把正解精簡。題庫檢查之外，可以用 docs/_length_fix.json 那段檢查程式自查。
10. 網站作答時會**自動打散選項順序**（甲乙丙丁、數字開頭的選項除外），所以解析裡不要寫「選 A」「第一個選項」，直接寫選項內容。

## 題目欄位
```json
{
  "id": "eu-012",                 // 用指定的前綴＋三位數，不可和別人重複
  "unit": "歐洲",                  // 單元名稱：通論單元名或區域名（見 _data_lists.md）
  "level": "eu-1",                // 關卡代碼（見 _data_lists.md）
  "region": "歐洲",               // 通論題填「通論」；臺灣題填「臺灣」；區域題填該區域
  "concepts": ["clim-current", "clim-sea"],   // 只能用 concepts.json 的代碼，第一個是主要概念
  "type": "single",
  "status": "確認",
  "source": "課本概念：…",
  "stem": "題幹",
  "figure": { … },                // 選填
  "options": ["…", "…", "…", "…"],
  "answer": 1,                    // 0 起算
  "explain": "解析",
  "check": { … }                  // 有數字或圖上判讀時必填
}
```

## 題型 type
| type | 說明 | 必要欄位 |
|---|---|---|
| single | 單選 | options, answer |
| click | 圖上點選：選項＝圖上標記的名稱 | figure 加 `"pick": true`；options 是標記名稱 |
| chain | 連鎖題組：同一張圖連問 2–4 小題 | parts: [{stem, options, answer, explain, concepts?, check?}] |
| clue | 線索猜地：線索逐一揭開 | clues: [3–4 條，由難到易], options, answer |
| order | 排序 | items, answer（正確順序的 index 陣列） |
| match | 配對 | left, right（數量相同）, answer（每個 left 對到的 right index） |
| decode | 原理解碼：給區域現象，選造成它的通論原理 | options 是「原理」 |
| compare | 跨區比較：同一原理在兩區產生不同結果 | 可以是單選，或用 parts 分小題 |
| transfer | 遷移題：先用臺灣例子確認原理，再換到其他區域 | **用 parts**：第 1 小題問臺灣例子（concepts 同一原理），第 2–3 小題換到本區域應用 |

區域魔王題（level 為 `xx-boss`）：用 chain，三小題分別是「自然」「人口（含文化）」「產業」三層面，串成一個情境。

## 圖表 figure（全部由程式繪製，不可用網路圖片）
```json
{"type": "climograph", "data": "climate/world-wmo-1991-2020.json", "station": "東京", "label": "甲地", "hideTotals": true}
{"type": "climographs", "data": "climate/world-wmo-1991-2020.json", "stations": [{"station": "倫敦", "label": "甲"}, {"station": "華沙", "label": "乙"}], "hideTotals": false}
{"type": "region-map", "basemap": "basemap/world-countries-ne50m.json", "bbox": [-25, 34, 45, 72], "highlight": ["FRA"],
   "data": "climate/world-wmo-1991-2020.json",
   "points": [{"station": "倫敦", "label": "甲"}, {"label": "乙", "lat": 52.2, "lon": 21.0}], "tropics": false, "pick": false,
   "texts": [{"text": "大西洋", "lat": 50, "lon": -18}]}
{"type": "polar-map", "basemap": "basemap/world-countries-ne50m.json", "pole": "N", "edge": 50, "highlight": ["RUS"], "points": [...]}
{"type": "pyramid", "data": "population/un-wpp-2024.json", "country": "日本", "year": "2023", "label": "甲國"}
{"type": "pyramids", "data": "population/un-wpp-2024.json", "items": [{"country": "奈及利亞", "year": "2023", "label": "甲國"}, {"country": "義大利", "year": "2023", "label": "乙國"}]}
{"type": "tw-stations", "data": "climate/tw-cwa-1991-2020.json", "basemap": "basemap/taiwan-ne10m.json", "stations": [{"station": "基隆", "show": "precipTotal"}]}
{"type": "diagram", "id": "orographic", "opts": {"a": "甲", "b": "乙"}}
```
- 溫雨圖：`label` 可以隱藏站名（例如「甲地」）讓學生判讀；`hideTotals: true` 隱藏年均溫、年降水量文字。
- region-map 的 bbox 是 [西界經度, 南界緯度, 東界經度, 北界緯度]；跨 180 度經線時東界可以 >180（例如 [110,-50,200,10]）。區域預設 bbox 見 units.json 各區域。
- 地圖上的點優先引用測站（`station`＋`data`），座標最準。沒有測站的地點（海峽、山脈、運河）可給 lat/lon，用公認的位置，誤差 1 度內。
- 一張地圖的點最多 4–5 個，標籤用甲乙丙丁或地名。
- 示意圖 diagram 可用：orographic（迎風背風，opts a/b）、raintypes、pressure（opts a/b/c）、fronts、season（opts lat/label）、monsoon（opts island/a/b）、compass、timezone。
- 人口金字塔 2050 年是推估值，圖上會自動標示「推估」；題目若用 2050 要說「推估」。
- 圖上點選（click）只適用 contour、graticule、town、region-map、polar-map、tw-stations（加 `"pick": true`）。

## 自動驗算 check（validate.js 會用程式重算）
```json
{"kind": "climate-value", "data": "climate/world-wmo-1991-2020.json", "values": [{"station": "東京", "prop": "wettest", "eq": 9}, {"station": "首爾", "prop": "annualRange", "gt": 25}]}
{"kind": "climate-rank", "data": "climate/world-wmo-1991-2020.json", "prop": "precipTotal", "pick": "max", "stations": ["甲對應站", "乙對應站", "丙", "丁"]}
{"kind": "pyramid-value", "data": "population/un-wpp-2024.json", "values": [{"country": "日本", "year": "2023", "prop": "old", "gt": 25}]}
{"kind": "pyramid-rank", "data": "population/un-wpp-2024.json", "prop": "young", "pick": "max", "items": [{"country": "奈及利亞", "year": "2023"}, {"country": "日本", "year": "2023"}]}
```
- climate 的 prop：tempAvg、precipTotal、annualRange（年溫差）、warmest／coldest（月份 1–12）、wettest／driest（月份）、janTemp、julTemp、janPrecip、julPrecip、summerShare（5–9 月降水占全年比例，南半球要小心）、alt、lat。
- pyramid 的 prop：young（0–14 歲 %）、work（15–64 %）、old（65 歲以上 %）、dependency（扶養比）、sexRatio（性別比）、total（百萬人）。
- climate-rank／pyramid-rank 的 stations／items 必須和 options 順序一一對應，answer 指向最大或最小的那一個。
- chain 的小題也可以各自帶 check。
- 題幹或解析引用的每一個數字，都要被某個 check 驗到（eq 允許 ±0.05）。

## 原理卡（只有通論出題者要寫）
`data/cards/<單元>.json` 的 `cards` 物件，key 是概念代碼：
```json
"land-glacial": {"title": "冰河地形", "text": "說明 2–4 句，\n 可換行", "tip": "選填：一句口訣", "figure": { …選填，同題目圖表… }}
```
每個你負責的概念都要有一張卡。

## 寫完要做
1. `cd /d/geo-quest && node scripts/validate.js 2>&1 | grep -F "[你的前綴"` 只看自己的錯誤，修到沒有錯誤為止（其他人的檔案可能還在寫，不用管）。
2. JSON 用 UTF-8、2 格以內縮排皆可；不要動別人的檔案、不要動 src/、scripts/、units.json、concepts.json、manifest.json。
3. 最後回報：題數（各關幾題）、用到哪些概念、哪些地方不確定或刻意沒出。
